できること

      
運用で困りやすいところを、抽選の前に決めておける形にしています。

      

        
重み付け
FC歴や口数などの列を重みにできます。1未満は1に、上限を超える値は上限に丸めるので、特定の人だけ極端に有利になることはありません。上限は抽選ごとに決めます（既定は2.0）。

        
重複申込の除外
同じ申込番号が複数あれば、最初の1件だけを残します。名前を貼るリスト入力では、全角半角、大文字小文字、先頭の @ をそろえてから重複を数えます。除外した件数は締切文に入ります。

        
補欠
当選の次の順位から、補欠を必要な人数だけ決めておけます。辞退が出たときは、補欠の順番どおりに繰り上げるだけで、再抽選は要りません。

        
当落CSV出力
全申込の順位、重み、当落をCSVにして、そのままコピーできます。基盤への当落反映や、問い合わせ対応の控えに使えます。

        
投稿文テンプレ
告知、締切、結果の3種を、「ラベル: 値」の1行ずつで出します。X向けの140字メーター付きです。検証ページは、この投稿文を貼るだけで再計算できます。

        
個人情報の列を使えない設計
メール、電話、氏名、住所、生年月日などの列名を含む列は、申込番号に選べません。申込番号だけで当落を決めるので、公開する verify.json に個人情報が入りません。

      

    

  


  

    

      
主催者も運営者も、締切後に結果をいじれない理由

      
仕組みは、コミット・リビールとハッシュ関数だけです。

      
    
        
  1. 1乱数は、締切前にハッシュ化して公開済みです。後から別の乱数に差し替えると、公開した値と合いません。
    2. 
        
  2. 2申込リストのハッシュは、締切時に公開します。足したり消したりして当選者を動かすと、ハッシュが変わります。
    3. 
        
  3. 3順位は、乱数と申込番号だけから決まる計算です。裁量が入る余地がなく、誰でも同じ手順で再計算できます。
    4. 
      

      

        
コミット・リビール
先に「指紋」だけを公開し、あとで中身を明かす方式です。中身を明かしたとき、指紋と合うかどうかで、約束を守ったかを確かめられます。

        
SHA-256
どんな文字列からも64文字の指紋を作る関数です。元の文字列を1文字変えるだけで、指紋はまったく別のものになります。

        
重み付き抽選（Efraimidis–Spirakis）
各申込に、重みで有利さが変わる乱数のキーを付け、小さい順に並べる方法です。重みが同じなら全員が公平に当たります。

はじめる前に

      
よくある疑問です。

      
無料でどこまで使えますか？
申込1,000件までの抽選を、回数の制限なく作れます。verify.json、当落CSV、告知文テンプレートまで使えます。料金は検討中です。

      
個人情報は本当に送られませんか？
申込CSVは、あなたの端末のブラウザの中だけで読み込みます。このページは外部と通信せず、フォントも端末のものを使います。送信するコードはこのページにありません。保存するのは、秘密ファイルと抽選のメタ情報をこのブラウザのlocalStorageに置くことだけで、画面から削除できます。

      
既存の基盤（Bitfan等）と併用できますか？
申込を受け付けている基盤から、申込番号の列を含むCSVを書き出せる場合は、そのCSVを読み込んで使えます。基盤との自動連携はありません。当落の反映は、当落CSVを見ながら主催者側で行います。

      
再抽選が必要になったら？
公開済みの結果を差し替えず、新しい抽選として作り直してください。新しいコミットメントを告知し、再抽選の理由を添えて公開すれば、元の結果とあわせて検証できます。進め方の相談は伴走プランで受けます。

      
法的にはどういう位置づけですか？
本サービスが保証するのは、公開された申込リストと乱数から結果を再計算できることだけです。抽選のルール、景品の扱い、景品表示法などへの適合は、主催者の側で確認してください。申込リストの中身が正当かどうかも、本サービスは確かめません。

    仕組み
    
    
    
      
    フェアドローは、コミット・リビールとSHA-256だけで、抽選の結果を後から再計算できるようにします。現在の方式は fairdraw/2 です。fairdraw/1 で作った記録も、検証ページで引き続き確かめられます。以下が全文です。
    

      
    この仕組みが保証すること
    
      
      
        
    • 乱数（seed）は、締切前に公開したコミットメントと一致するものだけが使えます。
      • 
        
    • 公開された申込リストと乱数から、当選と補欠が1通りに決まります。
      • 
        
    • 誰でも、このページのコードで同じ結果を再計算できます。
      • 
      
    
      
    保証しないこと
    
      
      
        
    • 申込リストの中身が正当かどうか。公開乱数を使えば、結果を見ながらリストを調整することはできなくなりますが、実在しない申込が混ざっていないかは確かめられません。公開された申込番号の一覧を、参加者が自分の申込と照らして確かめてください。
      • 
        
    • 抽選のルールや景品の扱いが、法令に適合しているかどうか。
      • 
      
    

      
    公開乱数（fairdraw/2）が防ぐこと
    
      
      
        
    1. fairdraw/1 では、主催者は乱数を知っているので、締切のハッシュを出す前に申込を足し引きして何通りも試算し、望む当選者が出るリストを選べました。
      2. 
        
    2. fairdraw/2 は、締切後に確定する外部の値（beacon_value）を最終シードに混ぜます。リストを確定する時点では誰もその値を知らないので、リストを調整して結果を狙えません。
      3. 
        
    3. 値の出どころ（beacon_source）はコミットメントに含めて締切前に公開します。結果を見てから、都合のよい値や出どころに差し替えることもできません。
      4. 
      
    
      
    出どころには、主催者が操作できず、誰でも同じ値を確認できるものを選んでください。申込の締切より後に確定する値であることも条件です。
    

      
    アルゴリズム（fairdraw/2）
    
      
    ハッシュはSHA-256（crypto.subtle.digest）で、16進の小文字です。文字列はUTF-8として扱います。
    
      
      
        
    1. シード: seed は乱数32バイトの16進（64文字）。crypto.getRandomValues で作ります。
      2. 
        
    2. コミットメント: commitment = sha256(seed + "|" + beacon_source)。beacon_source は公開乱数の出どころを書いた文字列で、使わないときは空文字です。締切前に、commitment と beacon_source の両方を公開します。
      3. 
        
    3. 申込リスト: 各申込は {id, w}。id は申込番号の列で、前後の空白を除きます。空は拒否し、重複は最初の1件を残して除外します。w は重みの列で、無ければ1、数値でなければ1。w が1未満なら1に、上限を超えれば上限に丸めます（小数可）。メール、電話、氏名、住所、生年月日、年齢、性別などを含む列名は、id に選べません。
      4. 
        
    4. エントリールート: entries_root = sha256(id をコードポイント順に昇順で並べ、各行を id + タブ + String(w) にして、改行（LF）で連結した文字列)。締切時に公開します。
      5. 
        
    5. 最終シード: final_seed = sha256(seed + "|" + entries_root + "|" + beacon_value)。beacon_value は締切後に確定した値を、宣言した表記のまま書いた文字列です。使わないときは空文字です。
      6. 
        
    6. 各申込のキー（Efraimidis–Spirakis の重み付き非復元抽出）: h = sha256(final_seed + "|" + id)。u = parseInt(h の先頭13文字, 16) / 1613（0以上1未満）。u が0なら u = 2-52。key = -ln(u) / w。
      7. 
        
    7. 順位: key の昇順。同じ値のときは id のコードポイント順。先頭N件が当選、次のM件が補欠です。
      8. 
        
    8. 公開データ: verify.json に、schema（fairdraw/2）、タイトル、N、M、重み上限、beacon_source、beacon_value、commitment、seed、entries_root、final_seed、全申込（id と w）、winners、waitlist、日時を入れて公開します。
      9. 
        
    9. 検証: 次の5項目を独立に再計算し、すべて一致すれば検証成功です。(1) sha256(seed|beacon_source) = commitment。(2) 申込リストから再計算した entries_root が一致。(3) sha256(seed|entries_root|beacon_value) = final_seed。(4) 再計算した上位N件が winners と順序まで一致。(5) 次のM件が waitlist と一致。
      10. 
      
    
      
    リストを貼る入力モードでは、アルゴリズムに入る前に名前をそろえます。NFKC正規化、ゼロ幅文字（U+200B〜U+200D、U+FEFF）の除去、前後の空白の除去、先頭の @ を1つ除去、小文字化の順です。そろえたあとの重複は最初の1件を残します。この前処理はアルゴリズムの外にあり、verify.json の id は、そろえたあとの名前そのものです。
    

      
    fairdraw/1 との違い
    
      
      
        
    • コミットメントは sha256(seed) です。公開乱数の出どころは持ちません。
      • 
        
    • 最終シードは sha256(seed + "|" + entries_root) です。
      • 
        
    • verify.json に beacon_source と beacon_value はなく、schema は fairdraw/1 です。検証ページは schema を見て、式を切り替えます。

    投稿文から検証する
    
      
    告知文、締切文、結果文は、「ラベル: 値」の1行ずつで書きます。検証ページの「投稿を貼る」は、このラベルから値を読み取って再計算します。投稿のハッシュは先頭32桁＋「…」に短縮されていてもよく、そのときは先頭が一致するかを見ます。乱数（seed）だけは全64桁を載せます。
    

      
    再現用の擬似コード
    

    sha256(s) = SHA-256(UTF-8(s)) を小文字16進で表した64文字
cmp(a, b) = コードポイント順の文字列比較

// 締切前
seed          = 乱数32バイトの16進（64文字）
beacon_source = "2026-11-06 の日経平均株価終値（円、小数1桁）"   // 使わないときは ""
commitment    = sha256(seed + "|" + beacon_source)             // beacon_source とともに公開する

// 締切時
entries      = [{id, w}, ...]               // 重複は最初の1件のみ。w は 1 〜 max_weight に丸める
entries_root = sha256(
  entries を id の cmp 順に並べ、各行を id + "\t" + String(w) として "\n" で連結
)                                           // 公開する

// 締切後
beacon_value = "39123.4"                    // 使わないときは ""
final_seed   = sha256(seed + "|" + entries_root + "|" + beacon_value)
for each e in entries:
  h   = sha256(final_seed + "|" + e.id)
  u   = parseInt(h.slice(0, 13), 16) / 16**13   // 0 <= u < 1
  if (u === 0) u = 2**-52
  e.key = -Math.log(u) / e.w
ranked   = entries を key 昇順（同値は id の cmp 順）に並べる
winners  = ranked の先頭 N 件の id
waitlist = ranked の次の M 件の id

// fairdraw/1 は commitment = sha256(seed)、final_seed = sha256(seed + "|" + entries_root)
